# Three.js部屋編集アプリ

8種類の部屋形状と8段階の帖数を選び、間取り編集、家具配置、危険度評価、配置候補生成を行うWeb版です。既存のUnity版は `/api/v1` を引き続き使用します。

## 起動

リポジトリルートのPowerShellでAPIを起動します。

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-api.txt
.venv/Scripts/python.exe -m uvicorn api:app --app-dir src --host 127.0.0.1 --port 8000 --workers 1
```

別のPowerShellでWeb版を起動します。

```powershell
cd web
npm install
npm run dev -- --port 5173
```

`http://127.0.0.1:5173/` を開きます。Viteが `/api` をローカルAPIへ転送します。家具カタログに接続できない場合も部屋編集は可能で、家具画面の「再接続」で復旧できます。

```powershell
npm run build
npm run preview
```

プレビューも同じAPIへのプロキシを持ちます。配布する場合は `web/dist` と `/api` を同じオリジンで提供してください。公開・ホスティング移行は行っていません。

## 操作

- 初期選択は正方形・6帖。4.5、6、7、8、10、12、15、20帖から選択できます。1帖は1.62㎡です。
- L、逆L、凸、凹、S、逆Sは選択カードに形を表示します。床の多角形面積で拡縮するため、凹部分は面積に含めません。
- 2D画面の辺をドラッグすると両端が辺に垂直な方向へ同時に動き、隣接辺が伸縮します。丸い頂点は自由に動き、斜め壁も作れます。
- 寸法は各辺の実長を小数第2位まで表示し、面積・帖数も更新します。内部座標は表示桁に丸めません。
- 交差、非隣接辺の接触、重なり、潰れは赤表示になり、家具配置へ進めません。元に戻す、Ctrl/Cmd+Z、選択時の形へのリセットが可能です。ドラッグのキャンセルはEscです。
- 50cm未満の狭い部分は警告に留めます。計算量を制限するため、部屋の外接寸法は幅・奥行き各16mまでです。穴、曲線、頂点の追加・削除には対応していません。
- 「3D確認」はThree.jsで床・壁・家具を表示します。各辺の寸法を重ね、視点回転と拡大縮小ができます。間取りの辺・頂点の編集は2Dで行います。
- 家具を選んで室内をクリックして配置します。ドラッグ、1°単位のスライダー・微調整、未配置化、選択からの削除ができます。本棚・ベッド・椅子・テーブル・テレビはKenneyの3DモデルをAPIカタログ寸法に合わせて表示し、未登録の家具は従来の簡易立体で表示します。本棚・椅子・テーブル・テレビはUnity版で登録されたものと同じ形状です。テレビは家具一覧の「テレビ台」から配置します。
- 3D画面右上の「家具モデル／箱表示」で表示を切り替えます。通常は家具モデルを表示し、2Dへ移っても選択を保持します。表示切り替えで配置や評価結果は変わりません。選択中はオレンジ、不正配置は赤の外枠で示します。モデル読み込み中・失敗時は箱で表示し、失敗時は通知します。
- 壁への吸着は15cm・10°以内で作動し、2cmの隙間を空けます。開口部がある区間には吸着しません。回転スライダーは自由回転です。
- ドア・窓を選び、幅を指定して壁をクリックします。斜め壁でも位置と幅を壁沿いに測ります。ドア前の50cmは家具を置けません。
- 家具配置後に「部屋の形を編集」へ戻ると下書き編集になります。確定時に影響する家具・開口部を確認でき、部屋外などになった家具だけを未配置に戻します。形状プリセットを変更した場合は壁の対応が変わるため開口部を再配置します。
- 評価は選択した家具がすべて配置済みの場合に実行できます。候補生成は未配置家具を含めて実行でき、家具を固定することもできます。候補は明示的に適用したときだけ反映し、現時点の部屋と固定家具を再検証して評価し直します。
- 編集後の評価・候補には変更前であることを表示します。古い危険領域を現配置に重ねません。通信に失敗しても編集内容を保持し、候補の結果取得を再開できます。「結果待ちを終了」はサーバー計算を停止しません。
- 初期表示と形状・サイズ変更時のみ約350msの演出があります。OSの「動きを減らす」設定に従います。

ブラウザーを再読み込みすると編集内容は初期化されます。アカウント保存・永続保存は今回の対象外です。

## 家具3Dモデルの追加・差し替え

Kenney Furniture Kit 2.0の配布物は `assets/kenney/furniture-kit/source/` にローカル保管しています。GLB形式も含まれるため、今後の家具追加では同梱GLBを直接利用できます。[資産の配置・Git管理・利用手順](../assets/kenney/furniture-kit/README.md) を参照してください。ライセンス原文は同ディレクトリの `License.txt`、Web配布用のコピーは `web/public/models/kenney-license.txt` です。

`web/src/furniture_models.js` の `MODEL_REGISTRY` がUnity版のモデルライブラリに相当します。APIカタログの `model_id` と対応させ、表示用の静的なGLBを登録します。アップロード画面、アニメーション、スキニング、圧縮形式用の追加デコーダーは対象外です。

1. モデルと必要なテクスチャを一つのGLBにまとめ、`web/public/models/` に配置します。
2. 登録表へAPIの `model_id`、GLBのURL、`rotationCorrection: [0, 0, 0]` を追加します。URLの先頭には既存の本棚エントリーと同じ `import.meta.env.BASE_URL` を使用します。
3. 上方向を+Yに揃えます。向きの補正値はXYZオイラー角、単位は度です。正面を持つモデルは+Zを基準としますが、家具ごとの評価上の方向を優先します。ベッドの枕側はAPIの `pillow_side: WEST` に合わせて-Xへ揃えます。
4. 向きの補正後に外接寸法を幅・高さ・奥行きそれぞれAPIの寸法へ拡縮し、底面中心を配置原点に揃えます。元の縦横比はカタログ寸法に従って変化します。天井設置の家具は上端を部屋の天井高に合わせます。
5. モデル表示と箱表示を切り替え、0°・90°・任意角度で位置、正面、接地、占有範囲を確認します。配置制約・選択判定・評価はカタログ寸法を使用し、モデルの細かな形状には依存しません。

モデルはURL単位で一度だけ取得し、資産を共有した表示インスタンスを作ります。未登録のIDは箱で表示します。読み込み失敗はページ内で再試行を繰り返さず、ファイル・接続を修正してページを再読み込みすると再取得します。空のモデルや幅・高さ・奥行きがゼロのモデルも箱表示に戻ります。

### 本棚の出典と再生成

- 元資産: `unity/Assets/KenneyFurniture/bookcaseOpen.fbx`。FBXのCreatorに `Model created by Kenney (www.kenney.nl)` と記載されています。
- Unity側の参照: `KennyShelf.prefab` → `ModelLibrary.asset` の `shelf` エントリー。
- Web配信用: `web/public/models/bookcase-open.glb`。形状960頂点と木材色 `#e59964` を保持し、静的なPBRマテリアルに変換します。資産を追加・配布するときは、その資産の配布元の利用条件も記録してください。

再生成は `web` ディレクトリで実行します。

```powershell
npm run models:convert
```

変換スクリプトは同梱FBXのUVブロックにある閉じ括弧の余分なインデントをメモリ上で補正します。Unity側のFBXとPrefabは書き換えません。生成したGLBもリポジトリに含め、通常の開発・ビルド時に変換を要求しません。

### ベッドのモデルと頭側

- 配布元資産: Furniture Kit 2.0の `Models/GLTF format/bedSingle.glb`（Kenney、CC0）。`web/public/models/bed-single.glb` へ内容を変えずにコピーしています。配布用ライセンスは同じディレクトリの `kenney-license.txt` です。
- 元モデルの独立した `pillow` メッシュは-Z側にあります。登録表の `rotationCorrection: [0, 90, 0]` により-X側へ向け、APIカタログの `pillow_side: WEST` と一致させています。
- 回転0°で頭側は2D間取りの左、90°で上、180°で右、270°で下です。3Dではカメラの向きにより画面上の左右は変わりますが、枕とヘッドボードのある端が頭側です。箱表示でも枕は同じ側です。
- 寸法はAPIの幅1.5m・奥行き1.0m・高さ0.75mへ合わせています。これは現在のカタログのサンプル寸法であり、一般的なシングルベッドの製品寸法を表すものではありません。
- `contracts/v2/bed-head.json` は実際の評価APIから生成した頭側領域です。`web/tests/bed_model.test.js` が0°・90°・180°・270°・37°の実GLB枕頂点の包含、床への接地、占有範囲、箱表示との一致を検証します。Python側の `tests/test_bed_model_contract.py` は、この領域が現在のAPI出力と一致することを検証します。

APIの頭側定義を変更した場合は、次のコマンドで領域データを再生成し、Webモデルの向きも確認してください。

```powershell
.venv/Scripts/python.exe scripts/export-bed-head-contract.py
```

### 椅子とテーブル

Unityの `KenneyChair.prefab` と `KenneyLowTable.prefab` が参照する `chair`、`tableCoffeeSquare` と同じFurniture Kit 2.0のGLBを使用します（Kenney、CC0）。

| API model_id | 配布元GLB | Web配信ファイル | 向きの補正 |
| --- | --- | --- | --- |
| `chair` | `chair.glb` | `web/public/models/chair.glb` | Y軸180° |
| `table` | `tableCoffeeSquare.glb` | `web/public/models/table-coffee-square.glb` | なし |

椅子は元モデルの背もたれが-Z側にあるため180°回し、Webでは背もたれを+Z側、正面を-Z側に合わせます。これはAPIの前方（間取りの北/+Y）と一致します。テーブルは正方形ローテーブルの形状を、現在のカタログ寸法（幅0.75m・奥行き0.50m・高さ0.75m）に合わせて拡縮します。椅子もカタログの幅0.25m・奥行き0.25m・高さ0.50mに合わせます。製品の実寸への変更は行っていません。

`web/tests/chair_table_models.test.js` で実GLBの読み込み、接地・寸法、0°・90°・37°の占有範囲、椅子の背もたれ方向、選択、箱表示への切り替えを検証します。

### テレビ

Unityの `KenneyTV.prefab` と同じ `televisionModern` を使用します。Furniture Kit 2.0の `Models/GLTF format/televisionModern.glb` を内容を変えずに `web/public/models/television-modern.glb` へコピーしています（Kenney、CC0）。

Web/APIの既存IDは `tv_unit` で、家具一覧の表示名は「テレビ台」です。この項目を配置すると薄型テレビの3Dモデルを表示します。Unity側の独自ID `TV` はAPIのIDではないため、Web登録では `tv_unit` に対応付けています。独立した家具種類の追加やUnity設定の変更は行っていません。

元モデルの画面は+Z側を向くため、Y軸180°の補正でWebの前方（間取りの北/+Y、Three.jsの-Z）に合わせます。登録済みモデルのテストで0°・90°・180°・270°・37°の画面方向、寸法、占有範囲、選択・箱表示切り替えを検証します。

表示は既存カタログの幅0.75m・奥行き0.50m・高さ0.50mに合わせます。モデルはテレビ本体とその脚で、別の収納台は含みません。危険度評価は従来の `tv_unit` の寸法・ルールを使用し、台からテレビ本体が落下する挙動を新たに評価するものではありません。

## API v2

`schema_version: 2`、`evaluation_version: 3`。API v1のフィールド・単位・評価経路は変更しません。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/v2/catalog` | 日本語名・家具の寸法（m）・規則 |
| POST | `/api/v2/evaluate` | 多角形部屋での評価・危険領域・床面積 |
| POST | `/api/v2/optimization-jobs` | 202、ジョブID・revision |
| GET | `/api/v2/optimization-jobs/{id}` | 状態・配置候補 |

- 部屋の `vertices` は `{id,x,y}` の順序付き頂点列です。単位はm、2Dのx右・y上、閉じる頂点の重複は不要です。時計回り・反時計回りの両方を受け付けます。Three.jsでは `(x,height,-y)` に変換します。
- 辺IDはその辺の始点の頂点IDです。開口部は `edge_id`, `offset_m`, `width_m`, `placed` で表現し、距離は始点から次の頂点へ測ります。未配置の開口部は以前の辺IDを保持して再配置できます。
- 家具の `x_m`,`y_m` は底面中心です。`rotation_deg` は時計回りの `[0,360)`。内部の25cm単位・外接矩形座標への変換をAPI層に集約しています。
- `revision` は編集で増加し、評価・候補生成の要求と応答で往復します。
- 応答の `regions[].points` もメートル単位です。凹部で分割された危険領域は同じ `scenario_id` を持つ複数のregionとして返し、避難経路はシナリオ単位で1回評価します。
- 形状、頂点ID、家具ID、開口部の範囲・重なり、不正な家具配置はサーバーでも検証し422を返します。候補生成では修復可能な未配置・不正配置の家具を許容しますが、固定家具は事前検証します。
- v1とv2のジョブ記録は分離し、既存の2プロセスワーカーを共有します。各ジョブストアは最大32件、完了後の期限は1時間、再起動後には残りません。

サンプルは `contracts/v2/`、WebとPythonが共有する全64プリセットは `contracts/room-presets.json` にあります。

## 評価の幾何モデル

Shapelyで部屋内への包含、交差、クリップを計算します。四隅だけの判定ではなく家具底面全体を検証するため、凹部をまたぐ家具を拒否します。壁への吸着、壁面支持、開口部、窓との距離も実際の辺を使います。

経路評価は25cm格子の近似です。セル全体が床に含まれる場合だけ通行可能とするため、部屋外・凹部を通過する架空の経路を作りません。出口はドア位置から最も近い室内セルへ接続し、その接続線も各危険シナリオで検証します。一方、狭い通路や斜め壁の境界では、実際には通れる場所が到達不能と判定される場合があります。この制約は評価画面に表示します。基礎の危険評価モデルは [危険評価の設計](safety-design.md) を参照してください。
