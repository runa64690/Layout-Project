# 配置の危険評価 v2

## 目的と根拠

就寝・着座場所への転倒／落下と、平常時・被災シナリオでの避難経路閉塞を配置提案に直接反映する。判定はサンプル家具の矩形モデルに対する条件確認であり、負傷確率、地震の物理予測、安全保証ではない。

以下は2026-10-08に確認した一次資料。推奨事項をそのまま数値基準と読み替えず、実装上の仮定を区別する。

| ID | 公的資料 | 本システムが参照する推奨 |
|---|---|---|
| FDMA-placement | [総務省消防庁：家具の配置にも工夫](https://www.fdma.go.jp/publication/database/kagu/post7.html) | 壁を背にした家具から就寝位置を高さ分離す、または側方に置く。転倒しても出入口を塞がない配置。固定だけで万全とは扱わない |
| CAO-layout | [内閣府：地震に備える](https://www.bousai.go.jp/kohou/kouhoubousai/h28/83/special_03.html) | 寝る・座る場所、出入口や避難経路への配慮。配置と固定の両方を行う |
| TFD-handbook | [東京消防庁：家具類の転倒・落下・移動防止対策ハンドブック（令和6年1月）](https://www.tfd.metro.tokyo.lg.jp/learning/elib/kagutenhandbook.html) | 冊子7–8ページ：配置、10–16ページ：器具と設置条件。資料の住宅とオフィスの記述を混同しない |
| TOKYO-bedroom | [東京都：東京くらし防災33ページ](https://www.bousai.metro.tokyo.lg.jp/content/kb2023/pageindices/index33.html) | 就寝時のガラス・照明落下への対策、飛散防止フィルム・カーテン |

## 危険モデルと明示的な仮定

| ルール | 実装 | 分類・限界 |
|---|---|---|
| 転倒源 | 現行カタログで転倒方向を持つ棚・テレビ台 | 対象選定は現モデル。台上のテレビ形状や収納物は未モデル化 |
| 転倒範囲 | 各家具面から家具高さ分の矩形。部屋内に多角形クリップ | 前方の高さ分はFDMA-placementを幾何化。後方・側方への適用は検証用仮定 |
| 方向 | 自立配置は前後左右を**独立**に確認。前方をprimaryとする | 同時に四方向へ倒れたものとして扱わない。発生確率は与えない |
| 壁の支持 | 背面の全幅が開口のない壁に沿い、角度差5°以内、背面両端の最大距離10cm以内なら後方のみ省略。側方は残す | 閾値と支持の扱いはモデル上の仮定。壁の強度を検証するものではない |
| 保護対象 | ベッド全体・椅子全体の平面形状 | 人体寸法・滞在時間は未モデル化 |
| 頭側 | ベッド内部の頭側50cm（家具幅が不足する場合は全幅） | 表示補助。ベッド全体で曝露を検査し、頭側だけを保護する設計ではない |
| 天井照明 | 真下の平面形状が落下領域 | 横揺れ・破片の拡散は未モデル化。照明は平常時の床障害物にしない |
| 窓 | 窓線分と保護対象の最短距離d[m]、近接点 `1/(1+d)` | 数式は比較用仮定。危険／安全の距離境界は定めず、旧50cm飛散帯は描かない |
| ドア前 | 開口幅×室内奥行50cmを家具配置禁止とする | 奥行は検証用仮定。開き戸の扇形・人幅を保証するものではない |
| 避難解析 | 25cm四近傍格子、家具と交差するセルを閉塞扱い | ラスター近似。細い斜め隙間や人の体幅は保証しない |

ベッドは長辺両側、椅子は前方の幅1セルの帯から、平常時に空いているセルを出発候補とする。転倒後に新しい出発位置を都合よく選び直さず、元の候補が全部塞がれば不成立。各シナリオの占有セルを平常時障害物へ追加する保守的近似を使い、元家具の場所が必ず空くとは仮定しない。いずれか一つの実在するドアへ到達すれば、その対象・シナリオの経路条件を満たす。

判定対象は平常時、および家具一つ・方向一つの転倒または照明一つの落下。複数家具の同時被災、滑動、収納物、人体損傷、揺れ・建物階数は今回の対象外。出口なし、またはベッド・椅子なしは未評価項目として明示する。

## スコアと提案順位

`valid` は室内・非重複・ドア前確保などの幾何判定。別の `safety.status` が、評価した条件に対して `met`（達成）、`unmet`（未達）、`not_evaluated`（不足情報）を返す。違反があり、さらに未評価項目がある場合はunmetと未評価理由の両方を返す。

安全違反Vは、転倒／落下と保護対象の交差1件、対象・シナリオごとの到達不能1件をそれぞれ数える。全方向の重複面積A[m²]と、そのうち主要方向の面積P[m²]も記録する。Aはシナリオ別の面積の和であり、同時被災面積ではない。

候補の順位は `(幾何違反の有無, V, A, P, 自然さC)` の辞書順。PはAが同等のときに正面を避けるためのタイブレークであり、発生確率の重みではない。自立家具を180°反転しても後方シナリオは残るので、向きを変えただけで条件達成になるとは限らない。

探索エネルギーは `1000 V + 100 A/(1+A) + 10 P/(1+P) + C/(1+C)`。下位項目を有界にすることで、自然さで違反1件を打ち消さない。最終選択には上記の正確な辞書順を使う。係数は探索用設定値であって、公的資料の危険率ではない。既存の幾何不正ペナルティは100万を基準とし、不正候補は最終応答から除く。

Cは既存の利用空間・動線・家具間距離・会話距離に、家具面と壁の距離／平行度、窓近接点を加えた値。重心を中央へ寄せる項目は標準で無効。壁寄せは棚・テレビ台の背面、ベッドの頭側／長辺を対象にし、開口のない壁区間のみ選ぶ。テーブル・椅子・照明を強制的に壁へ寄せない。

MCMC内部は対称な移動・回転・交換。連続移動は±0.2セル／±2セル、回転は±3°／±30°の混合。壁沿い調整は探索前の初期改善と探索後に行い、必ず再評価し辞書順で改善した場合だけ採用する。探索中の最良配置は間引き・burn-inで捨てない。多様性選択は安全順位の同じ層内に限定し、返す順序も辞書順を保つ。

未配置家具は床の大きい家具から配置する。幾何的な初期配置に失敗した場合は、探索ロックを保持し、最大12回まで移動可能家具の初期配置を作り直す。

十分な条件達成案が見つからなければ、幾何的に有効な未達案を残る危険付きで表示する。見つからないことを不可能の証明としない。

## 対策入力と操作

`restraint`: unknown / none / wall_bracket / belt / pole / pole_combination / other。`installation_confirmed` は利用者が設置を確認した記録であり、アプリによる耐力検証ではない。未配置・不明・対策なしでは確認済みにできない。位置・角度変更や未配置への変更で確認を解除する。探索の `fixed_keys` とは完全に別の属性。

窓の `film` / `curtains`: unknown / none / present。初期値は不明。対策属性は幾何的な危険範囲・違反数を減らさない。器具の適合・壁下地・天井強度などは公的資料と器具の説明書で確認する情報として表示する。

Unityの壁吸着は15cm・10°以内で開始、25cm・15°を超えて解除し、壁との隙間2cmを残す。角では評価値と固定された面・壁の走査順で決定し、吸着中は同じ壁を優先。開口部や衝突する吸着は不採用。ON/OFF可能で、スライダーと±1°操作は吸着しない。各値は操作性の仮定。

API座標・角度・カタログ寸法は維持し、任意の対策属性を追加。`schema_version=1`、`evaluation_version=2`、catalogのcapabilitiesで機能を識別する。旧入力は対策不明として受理する。新Unityは評価v2のAPIを要求する。

`breakdown` は解釈用の生の生活項目と安全エネルギー項目を含む。`total`/候補の`cost`は有界化後の探索エネルギー、`natural_cost`は生活項目の和なので、全breakdownの単純和をtotalとして扱わない。`fall_overlap_cells` は旧クライアント互換の「前方とベッドの重複セル面積」。新評価には `safety.overlap_area_m2` とissuesを使う。

古い候補適用時は現在の対策・窓情報と探索ロックを維持する。移動家具の設置確認を解除し、適用後に現在の部屋で再評価する。Unityは危険シナリオを一つずつ切替表示する。旧Tkinterは離散操作を維持し、同じ危険多角形にシナリオ名を付けて表示する。

## 再現手順

1. `.venv/Scripts/python.exe -m pytest -q`
2. `.venv/Scripts/python.exe scripts/export-contracts.py`
3. Unity 6000.3.6f1を `-batchmode -nographics -projectPath unity -executeMethod FurnitureLayout.Editor.LayoutSafetyChecks.Run -logFile outputs/unity-safety-checks.log` で実行する。
4. `.venv/Scripts/python.exe scripts/benchmark-safety.py`。配置済み・未配置・密集・ベッド固定、シード0/1/42を900ステップで比較する。

ベンチマークは要求、初期評価、全候補、条件達成数、違反数、候補間距離、時間を `outputs/safety-benchmark.json` に保存する。Unity検証は吸着と共通ポインター処理を実行し `outputs/unity-safety-checks.json` に結果を保存する。実機のマウス／タッチでの見た目・操作感は自動テストの対象とは区別する。

今回の実行結果は [検証記録](safety-validation.md) に掲載する。
