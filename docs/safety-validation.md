# 評価v2の検証記録（2026-10-08）

## 実行条件

Windows、Python 3.11のプロジェクト仮想環境、Unity 6000.3.6f1。
サンプル6家具。通常は16×16セル、密集条件は8×8セル。ドアは左壁offset=5、幅2セル。窓は上壁offset=5、幅2セル。1セル25cm。
乱数シード0/1/42、各900ステップ、burn-in250、間隔15、最大3候補。

再現コマンドとモデルの出典・仮定は [設計資料](safety-design.md)。実験プログラムは [benchmark-safety.py](../scripts/benchmark-safety.py)。全入力・初期評価・候補配置・詳細指標は実行時に `outputs/safety-benchmark.json` に保存される。

全36候補は幾何的に有効。通常条件の9回で27件の条件達成候補を得た。密集条件では条件達成案は見つからず、危険が残る9件の参考案を返した。密集条件の候補間距離は小さく、多様性・探索の改善余地がある。この結果から条件達成配置の不存在は結論しない。所要時間はこの環境・小さなサンプルでの測定値であり、性能保証ではない。

候補間距離は家具ごとに、部屋幅で正規化したx差、部屋高さで正規化したy差、最小回転差/4の和をとり、家具数で平均した指標。人体距離や安全性を表す値ではない。

## 自動検証

- Python: 84ケース。API・別プロセスワーカー・連続幾何・危険シナリオ・窓距離・対策不変性・初期配置・探索ロックを確認。
- Unity: バッチモードの37アサーションを通過。C#コンパイル、吸着ON/OFF・開始／解除・角度・角の選択、開口と衝突の除外、対策情報のJSON往復、移動後の再確認、共通ポインターのプレビュー→確定／キャンセル、Python生成候補3件のUnity適用を確認。
- 互いに排他的な二つの転倒シナリオは、各々なら避難できるが合併すると閉塞するケースで、合併して評価していないことを確認。
- 既存のPython UIはインポート互換を確認し、危険領域と頭側表示を共通の多角形生成へ変更。

Unityの検証ログは `outputs/unity-safety-checks.log`、結果は `outputs/unity-safety-checks.json`。マウスと1本指タッチが呼ぶ共通ポインター処理を自動で実行した。物理マウス／タッチ端末での操作感、画面の目視確認はこのバッチ検証に含まれない。

## 次に検証すべき範囲

実寸入力、人体の通過幅、複数家具の同時被災、器具の実効耐力、滑動、収納物・破片は今回のモデルの外にある。窓との距離と器具の自己申告情報から負傷確率や危険低減率は算出していない。
